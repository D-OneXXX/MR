## 1. 结论摘要

第一轮不是“全绿”验收，而是把问题钉死：

1. **没有 P0。** 没有发现启动即崩溃、数据目录被污染、静默上传、静默重启或凭据落盘到 SQLite/日志的证据。
2. **6 个 P1 已被隔离实例稳定复现**，并已成为永久回归用例：在线 JSON/HTML 噪音过滤、条漫极速滚动当前视口饥饿、未补零页序、诊断 JSON 凭据泄漏、诊断描述未脱敏。
3. **2 个静态 P1 仍未自动化**：旧 `reading_log` 迁移非原子、更新安装脚本对非 ASCII 路径不安全。两者都可能造成数据/升级事故，优先于多数 P2。
4. **版本门禁与启动迁移的验收通过**：三端版本一致、故意漂移能在 `file:line` 处失败、恢复后幂等；`last_run_version` 迁移保留主题/语言/书库/进度。
5. **QA 自身先被审计并去污**：删除了由测试时序/选择器造成的假 P1，修正了条漫拖拽的 HUD 失效误判，知识库从“失败即入库”的污染状态收敛为可解释的回归集。

## 3. 运行时 P1（已自动化，当前为红）

### P1-1 未补零页码按字典序排列

- 位置：`src-tauri/src/source.rs:112,165,382`
- 复现：导入含 `1.png / 2.png / 10.png / 11.png` 的文件夹，调用 `list_entries`
- 期望：`1 → 2 → 10 → 11`
- 实际：`1 → 10 → 11 → 2`
- 根因：`FolderSource::open` 与 `ZipSource::open` 使用 `Vec::sort()` 字典序；`commands.rs` 已有 `natural_cmp`，但没有复用。旧夹具用三位补零，掩盖了该缺陷。
- 修复：文件夹与 ZIP/CBZ 条目统一改用 `natural_cmp`；保留补零/未补零混合回归。
- 回归：`reader:natural-order`（新增夹具，永久保留）

### P1-2 100+ 页极速滚动后当前视口持续空白

- 位置：`src/components/Reader/Webtoon.tsx:344-416`
- 复现：125 页条漫连续跳转 45 个滚动窗口，最终停在 55%·69/125；等待 3.4 秒后读取 DOM
- 期望：最终视口至少 1 张正文图，tiles ≤ 30，images ≤ 20，CLS ≤ 0.02
- 实际：`tiles=4, images=0, loadedImages=0, CLS=0`；scrollHeight 稳定，说明不是布局塌陷，而是图片请求饥饿
- 根因：`ensureTiles` 对每个中间窗口立即调用 `loadTile`，只做 `requestedRef` 去重，没有在飞上限、取消或最新窗口优先；后端 tile 请求串行，最新视口的请求排在大量过期窗口之后。
- 修复：滚动空闲约 120ms 后再取窗；在飞请求 ≤ 4；按代际取消过期窗口；最新视口优先队列；失败/取消后释放 `requestedRef` 键。
- 回归：`reader:webtoon-rapid`（本轮把原先只查 tiles/images 数量的弱断言，改为必须加载当前视口图片）

### P1-3 在线 JSON 清单未过滤 Logo/图标/广告/缩略图

- 位置：`src-tauri/src/online/direct.rs:163-184`
- 复现：回环清单含 7 个条目：1200×1800、900×1350、1600×1200 三张正文，128×128 logo、64×64 icon、728×90 ad、240×240 thumb
- 期望：只保留 3 张正文，记录过滤计数
- 实际：`pageCount=7`
- 根因：`parse_manifest` 只做 URL 规范化与尺寸合法化，不根据尺寸/面积做噪音过滤，也不去重。
- 修复：双尺寸条目在 `min(w,h) < 300 && area < 120000` 时剔除；缺尺寸条目保留（不猜测）；规范化后保序去重；日志只记录过滤数量，不记录完整 URL。
- 回归：`online:noise-json`

### P1-4 HTML 图集混入 Logo/广告时未过滤

- 位置：`src-tauri/src/online/html.rs:42-61`
- 复现：回环 HTML 的 `<header>/<nav>` 含 logo/icon/ad，`<main>` 含 3 张正文与 1 张 thumbnail
- 期望：剔除站点 chrome、Logo、广告、缩略图，保留 3 张正文
- 实际：所有 `<img>` 一律入页，`pageCount=7`
- 根因：纯正则逐个提取 `<img>`，不区分 `header/nav/footer/aside/main`，不看 `alt/class/id/width/height`，也不处理 `script/style/注释` 与 `<base>`。
- 修复：先剥离 `script/style/注释`；跳过语义 chrome 内的图片；按 `alt/class/id/URL basename` 的噪音词（logo/icon/banner/avatar/thumb/ad）过滤；有 `width/height` 时按小于 300 过滤；静态 HTML 无布局，需在文档声明“启发式过滤，不保证任意站点精确”。
- 回归：`online:noise-html`

### P1-5 诊断包中 JSON 引号键的 `api_key` 未脱敏

- 位置：`src-tauri/src/diagnostics.rs:244-284`
- 复现：写入错误消息 `{"Cookie":"session=SECRET_JSON_COOKIE","Authorization":"Bearer SECRET_JSON_TOKEN","api_key":"SECRET_JSON_KEY"}`，采集诊断包
- 期望：三个值全部变为 `<REDACTED>`
- 实际：`SECRET_JSON_KEY` 原样保留；`Cookie` 仅因内部 `session=` 被值规则命中，`Authorization` 仅因 `Bearer` 被值规则命中，属于偶然覆盖，不是键名规则生效
- 根因：`key_value_regex` 要求 key 后直接跟 `:` 或 `=`，没有覆盖 JSON 的 `key" :` 形式；`header_regex` 的 lead 字符集也不包含 `"`。
- 修复：先尝试按 JSON 解析并按键脱敏；失败再走正则。正则允许 key 与分隔符之间存在引号/空白；补 `"Cookie"/"Authorization"/"api_key"` 单测。
- 回归：`privacy:sanitize-json-credentials`

### P1-6 诊断描述中的路径/Token 原样进入 Prompt

- 位置：`src/features/diagnostics/prompt.ts:127`
- 复现：在“复现描述”输入 `C:\Users\RealName\Secret Comics\第02话.cbz token=SECRET_DESC_TOKEN`，读取 Prompt 预览
- 期望：描述与诊断包一样经过 `sanitize_text`
- 实际：`RealName / Secret Comics / 第02话 / SECRET_DESC_TOKEN` 全部原样出现在预览、复制与导出文本中
- 根因：`buildDiagnosticPrompt` 直接拼接 `description.trim()`；脱敏只发生在后端 bundle。预览页顶部“Sensitive credentials and local manga paths were sanitized before preview”因此是过度承诺。
- 修复：生成 Prompt 前把 description 交给后端 `sanitize_text`（新增命令或扩展现有 collect），保留预览可编辑；在脱敏结果返回前不要显示“已脱敏”。
- 回归：`privacy:sanitize-description`

## 4. 静态审计 P1（尚未自动化）

### P1-7 旧 `reading_log` 迁移非原子

- 位置：`src-tauri/src/db.rs:110-129`
- 证据：`execute_batch` 内连续执行 `ALTER TABLE ... RENAME`、`CREATE TABLE`、`INSERT`、`DROP TABLE`，没有显式事务。SQLite 默认逐句自动提交；若在 rename 后崩溃，下次启动时旧表已不存在，`ALTER TABLE reading_log RENAME` 会直接失败，应用无法打开书库。
- 期望：单事务内完成，失败回滚；启动时可识别并恢复 legacy 表。
- 修复：`BEGIN IMMEDIATE` 包住全部语句；提交失败回滚；迁移前检测 `reading_log_legacy` 残留并继续/恢复。
- 风险：升级用户的历史阅读统计可能丢失，或应用直接起不来。

### P1-8 更新安装脚本对非 ASCII 路径不安全

- 位置：`src-tauri/src/update.rs:1359-1418`
- 证据：`spawn_installer` 用 `std::fs::write` 写 UTF-8 `.cmd`，再用 `cmd.exe /C` 执行。`cmd.exe` 按 OEM 码页读取批处理内容；中文/emoji 安装目录、用户名或重启 exe 路径会乱码。此时应用已经退出，用户只看到安装失败或新版本不启动。
- 期望：任意合法 Windows 路径都能完成升级与重启。
- 修复：改用 PowerShell `-EncodedCommand`（UTF-16LE）或原生安装 API；失败时保留手动安装包与明确提示；不要只拒绝 `"`/`%` 就认为安全。
- 验证缺口：当前测试只覆盖 ASCII 临时目录，需增加中文用户名/中文安装目录的真实升级冒烟。

## 6. 验收结果

### 6.1 版本单一事实源

- `package.json.version = 0.11.0`，同步写入 `src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock`、`package-lock.json` 根字段。
- 前端 `vite.config.ts` 从 `package.json` 读取版本，注入 `__APP_VERSION__` 与 `__BUILD_COMMIT__`；`src/lib/version.ts` 只消费注入值，无第二副本。
- 故意把 `src-tauri/tauri.conf.json` 改为 `0.10.9` 后执行 `npm run version:check`：

  ```text
  [version] FAILED: version mismatch
    src-tauri/tauri.conf.json:4 版本 0.10.9 与 package.json:4 的 0.11.0 不一致
  ```

  退出码 1；随后 `npm run version:sync -- 0.11.0` 恢复，`version:check` 再次通过。
- `node --test scripts/version.test.mjs`：5/5 通过（精确行号、漂移报错、同步幂等、PATCH/MINOR/MAJOR 映射、降级保护）。
- `npm run build`：版本门禁 + `tsc` + Vite 多页构建通过；`dist/index.html` 与 `dist/recovery.html` 均产出。主 chunk 641.38 kB（gzip 190.95 kB），Vite 给出 >500 kB 警告，未阻断构建。

### 6.2 启动迁移

- `app_meta.last_run_version` 持久化；启动时读取旧版本并规划迁移。
- 任一版本变化清理内存页/缩略图/条漫缓存与 source 句柄；MAJOR/降级/未知才清理磁盘渲染缓存，避免每次补丁升级重新渲染全部书。
