# 真机冒烟报告（2026-10-19）

> **历史记录**：本文是 2026-10-19 在 `v0.2.0` 基线上的冒烟结果，**不是当前基线**。
> 当前版本为 `0.6.0`、`cargo test` 171 项；其中 P3-8「工作台选书静默切换」已修复。
> 当前冒烟清单见 [smoke-test.md](smoke-test.md)，当前实现见 [TECHNICAL.md](TECHNICAL.md)。


结论：**核心链路能跑通，但按 `docs/smoke-test.md` 的标准不通过。** 单页检测→OCR→翻译→擦除、缓存命中、暂停/继续都能工作；主要失败项是「二次执行不秒出」「整话批量 7/9 页翻译失败」「书库看板信息不完整」，另有冒烟文档与默认配置不一致的问题。

## 环境与方法

- 应用：`v0.2.0` dev 构建（Tauri 2 + WebView2 `155.0.4283.62`），`npm run tauri dev`。
- sidecar：`127.0.0.1:8500`，`device=cpu`，模型文件齐全。
- LLM：`llama-server`（`Index-Translate-9B.Q4_K_M`）`127.0.0.1:8080`，`n_ctx=8192`。
- GPU：RTX 4060 Laptop 8GB。测试期间 GPU 持续 100% 占用、显存 7.5GB（本机同时运行 Blender、Wallpaper Engine、浏览器、Qoder 等，**不是干净的空载环境**）。
- 测试书：书库中唯一可见的 9 页书（记为「测试书」）。未截取任何画面。
- 驱动方式：真实应用 + WebView2 远程调试 + Playwright，直接操作真实 DOM 与 Tauri 命令，未使用 mock。
- 说明：首轮自动化在断开 CDP 时使用了 `browser.close()`，这会让 WebView2 退出；改为直接断开连接后应用全程稳定。**这不是应用缺陷。**

自动化基线（本轮全部通过）：

- `cargo test`：34 个单元测试 + 2 个集成测试，含 200 页内存验收（37.22s）。
- `npx tsc --noEmit`、`node scripts/verify-spread.mjs`、`node scripts/verify-region.mjs`。

## 问题清单

### P0-1 冒烟起点不可达：翻译默认关闭且 Model 为空

数据库初始状态：

- `experimental_trans = false`
- `trans_model = ""`

结果是工作台/术语表入口全部隐藏；即使手动打开，翻译也会报「请在设置中填写翻译 Model」。这不是本轮改动，而是开发期为控制实验功能留下的默认值，但冒烟清单没有写这一段前置条件。

建议：在 `docs/smoke-test.md` 的「准备」中加入「设置 → 实验性功能 → 开启翻译；填写 Model（如 `index-translate`）」；或为冒烟准备一个专用 profile/种子配置。测试后已把这两项恢复为原值。

### P0-2 LLM 启动文档与脚本不一致

- `docs/smoke-test.md` 写「运行启动翻译代理.bat，或确认 8080 有服务」。
- `启动翻译代理.bat` 实际启动 `D:\llama.cpp\llm_batch_proxy.py`，监听 **8081**，把请求转发给 8080，自身不拉起 llama-server。
- 应用默认 Endpoint 是 `http://localhost:8080/v1`，并不经过 8081 的批量 JSON 代理协议。

建议：文档明确「应用直连 8080，请运行 `start-server.bat`；翻译代理仅用于 BallonsTranslator 批量协议」。或者统一启动脚本，避免用户只开代理导致 8080 不可用。

### P1-3 擦除结果没有缓存，二次执行不是「秒完成」

`wb_inpaint` 每次都会重新加载原图并请求 sidecar 的 lama；只有 OCR 存档（`page_ocr`）和翻译（`trans_cache`）有缓存。实测二次执行 8.7 秒。

建议：

1. 以 `book_id + page + 保留框哈希` 为键缓存擦除图（内存 LRU 或磁盘渲染缓存），或在 `page_ocr` 旁边存一份擦除成品。
2. `elapsedMs` 展示整步耗时（翻译 + 擦除 + 嵌字），而不是只显示翻译耗时；避免 `7 ms` 与用户体感不符。

### P1-4 本地 LLM 变慢时批量任务大面积失败

证据：

- 批量最终 2 成功 / 7 失败，失败文本一致。
- llama-server 日志显示请求在 30s 被客户端取消（`stop: cancel task`），但服务器继续算到 30–60s；有请求总计 59.5s，之后直接 `curl` 一句「おはよう」耗时 **1m46s**（prompt eval 59.6s / 38 tokens）。
- 同期 GPU 100%、显存 7.5GB、功耗仅约 36W，机器上还有 Blender 等 GPU 应用。
- 会话早期同一 LLM 响应正常（7 tokens/0.2s），说明是**环境中途恶化**，不是端点/模型名错误。

这更像本机 GPU 争用导致 LLM 不可用，而不是批量队列逻辑错误；但按验收标准仍算失败。建议：

1. 冒烟前关闭 GPU 重负载应用；llama-server 可加 `--parallel 1` 降低取消/排队副作用。
2. 应用侧给批量翻译加有限重试/退避，或把默认 `trans_timeout_s=30` 提高到 60–120s（设置页可配，但默认值对 CPU/争用环境偏紧）。
3. 失败页保留错误摘要（已有 `last_error`），并在看板展示成功/失败计数。

### P2-5 书库批量卡片状态与统计不合清单

`src/pages/Library.tsx` 的卡片标题是硬编码「批量预翻译进行中」，过滤条件却包含 `done / done_errors / failed`；只渲染状态徽标和进度条，没有清单要求的成功/失败计数。任务完成或失败后仍显示「进行中」。

建议：标题按状态切换（进行中 / 已完成 / 有失败），补 `成功 X · 失败 Y` 文案。

### P2-6 工作台的 OCR 不计入调用统计

设置页统计在完成 9 页批量 OCR 后仍显示「OCR 0 次」，翻译显示 6 次。`translate_texts_cached` 会写 `trans_log`，但 `wb_ocr` 路径没有写。清单步骤 4 要求 OCR/翻译统计都增长。

建议：在工作台 OCR 成功/失败后同样记录 `ocr` 调用，或明确统计只覆盖阅读器选区 OCR。

### P2-7 「载入页面」后没有页图预览

清单步骤 3 期望「载入页面 → 页图显示」。实际 `Workbench.tsx` 只在 `full`（检测结果尺寸）存在时渲染图片，所以用户点完载入只看到空白卡片，必须点「开始检测」才有画面。对于要手动选页码、确认页面的工作流，这是明显的反馈缺失。

建议：`page` 就绪即显示页图（框图层可叠加在图上），检测完成后再更新 `full` 尺寸。

### P3-8 工作台选书会在书库变化后静默切换

测试中书库顺序变化后，工作台默认选中了另一本 495 页的书，导致一次缓存验证实际跑到了错的书上（发现后改回测试书并通过）。如果用户正在操作，选书被外部刷新改掉会打断工作。

建议：仅在首次加载时设置默认书；后续刷新保留当前选择，或在选中的书消失时才回退。

## 环境异常（非本轮自动化触发）

测试期间观察到 `library.db` 被外部改动：

- 一本此前 `removed=1` 的 495 页书在 09:47 被恢复为 `removed=0`；
- 其阅读进度从 62 变为 71，`reading_log` 当日新增 10 页；
- 测试书的今日阅读页数也从 0 变为 16，但我们没有打开阅读器，只在工作台载入过页面。

应用进程只有一个，CDP 也只有一个页面。**无法确认是否有人/另一个实例同时使用该数据库。** 建议下次验收使用独立数据目录（例如临时 `LOCALAPPDATA` 或测试 profile），避免结论受外部写入污染。本轮批量、缓存、统计结论均以 9 页测试书为准。

## 建议修复顺序

1. 更新冒烟文档/启动脚本（P0-1、P0-2）——否则下一次验收仍会卡在起点。
2. 缓存擦除结果并修正耗时展示（P1-3）——直接对应清单「秒完成」。
3. 批量翻译超时与重试策略（P1-4）——决定整话预翻译能否在 CPU/GPU 争用环境可用。
4. 看板状态与计数（P2-5）、OCR 统计（P2-6）、载入页预览（P2-7）。
5. 工作台选书保持（P3-8）。

## 复现摘要

```bat
sidecar\launch.bat
D:\llama.cpp\llama-server.exe -m D:\models\index-translate\Index-Translate-9B.Q4_K_M.gguf ^
  --jinja --reasoning off --temp 0 -c 8192 --port 8080
npm run tauri dev
```

应用内：

1. 设置 → 实验性功能 → 开启翻译；翻译服务里 Model 填 `index-translate`；保存。
2. 工作台 → 选 9 页测试书 → 载入页面 → 开始检测 → 执行（保留全部框）。
3. 再次「载入页面 → 开始检测 → 执行」，记录整步耗时（本轮 8.7s）。
4. 整话预翻译 → 暂停 → 继续 → 等结束，查看 `batch_jobs` 成功/失败计数。
5. 回书库查看批量卡片。

本轮测试后已恢复 `experimental_trans=false`、`trans_model=""`，并关闭 sidecar、LLM 与 dev 应用。
