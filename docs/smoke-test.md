# 真机冒烟测试清单(阶段三:框选翻译 + 工作台 + 批量队列)

按顺序执行;每步都有"预期"和"异常处理"。哪一步不符合预期,把【上报格式】里的信息发给执行 agent。

## 准备

- [ ] **P1 安装 sidecar(仅首次)**:运行 `sidecar\setup.bat` —— 建 `.venv` + 装 Python 依赖(torch CPU 等)+ 下载模型到 `sidecar\models\`(约 700MB,一次性)。之后再启动只需 launch.bat。
- [ ] **P2 启动 LLM 服务(翻译要用)**:运行桌面的 `启动翻译代理.bat`,或确认 8080 端口已有服务:
      浏览器打开 `http://localhost:8080/` 或 `http://localhost:8080/v1/models` 有响应即可。
      不启动也能测检测/OCR/擦除,但步骤 ② 翻译会报错(这本身也是一次失败降级验证)。
- [ ] **P3 准备书**:书库里至少有一本书(没有就拖一个 cbz 进书库窗口,或点"扫描目录")。
      建议拿一话 20~60 页的卷做批量测试,太快太大都会影响体验。

## 1. 启动 sidecar

- [ ] 双击 `sidecar\launch.bat`(或 CMD 里运行它)。
- 预期:窗口输出 `[sidecar] listening on 127.0.0.1:8500 device=cpu models=...models`。
- [ ] 浏览器打开 `http://127.0.0.1:8500/health`,预期返回
      `{"ok":true,"device":"cpu","models":{"detector":"not_loaded",...}}`
      (not_loaded 是正常的,模型在首次推理时才加载)。
- ⚠️ 窗口保持开着,关窗 = 服务停。端口被占时:先 `set SIDECAR_PORT=8501` 再运行,同时去应用"设置页 → Sidecar Endpoint"改成 `http://127.0.0.1:8501`。

## 2. 启动应用

- [ ] 另开一个终端:
      ```
      cd C:\Users\Administrator\Desktop\manga-reader-tauri
      npm run tauri dev
      ```
- 预期:编译 1~5 分钟后弹出应用窗口(若已有旧的 dev 窗口开着,先关掉)。

## 3. 单页两步工作流(先验证链路通)

- [ ] 顶栏 → **翻译工作台**。
- [ ] 检查四下拉框:检测器=ctd(sidecar)/ OCR=mit48px(sidecar)/ 擦除=lama(sidecar)/ 翻译=OpenAI 兼容。
- [ ] 看 sidecar 健康行(点"刷新"):应为灰字 `sidecar cpu · 检测 ... · OCR ... · 擦除 ...`。
      红字"sidecar 不可达"→ 回步骤 1。
- [ ] 选书 + 页码 1 → **载入页面** → 页图显示。
- [ ] 点 **开始检测**:
      - 首次要加载 ctd 模型,按钮"检测中…"可能持续 10~40 秒,之后同会话内秒级;
      - 预期:页图出现蓝色文本框,每框左上角带识别出的日文;标题旁显示耗时 ms。
- [ ] 点几个不需要翻译的框(拟声词/页码/水印):变灰色虚线 = 已删除(不翻译、不擦除)。
- [ ] 点 **执行(保留 N 框)**:
      - 翻译每条几秒(取决于 LLM);lama 擦除 CPU 较慢,整页可能 10~60 秒;
      - 预期:图片变成擦除后的版本,保留框位置出现白色译文;下方出现 原文→译文 对照;
        toast 显示"完成:…";被删除框的区域画面保持原样。

## 4. 验证缓存秒出

- [ ] 同一页再点 **载入页面** → **开始检测**:预期按钮显示 **已秒出**、标题旁 **缓存秒出**(不调模型,即时)。
- [ ] 直接点步骤 ② **执行**:预期瞬间完成,toast 显示"X 条命中缓存"。
- [ ] (可选)设置页 → 翻译服务:OCR/翻译调用统计数字应增长。

## 5. 整话批量预翻译

- [ ] 工作台 → **批量预翻译(整话)** 卡片 → **整话预翻译**。
- 预期:卡片变进度条,`N / 总页数 页 · 成功 X · 失败 Y`,状态 `running`;已做过的页秒过。
- [ ] 点 **暂停**:状态变 `paused`(当前页会跑完再停)。
- [ ] 点 **继续**:回到 `queued`→`running`,从断点继续,页数不倒退。
- [ ] 跑完:进度 100%,状态 `done`(有失败页则 `done_errors`,开头连 3 页全失败则 `failed` 并写明原因)。

## 6. 看板进度

- [ ] 顶栏 → **书库看板**:应出现 **批量预翻译** 卡片,同样的进度条,约 3 秒刷新一次;
      跑满 100% 后仍可见,显示成功/失败计数。卡片上有"打开工作台"入口。

## 7. 验收:翻过的页秒出

- [ ] 批量跑完后,工作台翻到任意中间页 → **载入页面** → **开始检测** → 预期 **缓存秒出**。
- [ ] 直接执行步骤 ② → 预期全部命中缓存、秒完成。

## 8. 内存验收(自动,可复核)

- [ ] `cargo test` 里的 `memory_budget::two_hundred_pages_memory_growth_within_budget`
      就是路线图验收:构建 500 页 cbz → 连翻 200 页 → 断言页窗口 ≤5、缓存 ≤ 预算、
      进程增长 ≤50MB。本轮已通过。
- [ ] (可选)真机复核:阅读器连翻 200 页,任务管理器看进程内存增长 <50MB。

## 上报格式

哪一步 + 界面红字/toast 原文 + sidecar 窗口最后几行输出。例:
> 步骤 3 开始检测 → toast:"sidecar 推理异常:..." ;sidecar 窗口:`Traceback ... FileNotFoundError: data/models/...`

## 常见错误速查

| 现象 | 原因/处理 |
|---|---|
| 健康行红字"sidecar 不可达" | launch.bat 没开着,或端口不一致 → 核对设置页 Sidecar Endpoint |
| toast"系统缺少 ja OCR 语言包" | OCR 槽位选了 Windows 本地 → 换回 mit48px,或系统装日语语言包 |
| toast"翻译请求失败/翻译服务返回..." | LLM(:8080)没启动 → 跑 启动翻译代理.bat,或核对设置页翻译 Endpoint |
| 任务状态 failed"连续失败" | sidecar 中途挂了 → 看它窗口报错,重启后工作台再点"整话预翻译"(增量续跑) |
| "模型缺失:..." | 模型没下全 → 重跑 `sidecar\setup.bat`(或单独跑 `sidecar\download_models.py`) |
